RETRIEVAL-AUGMENTED GENERATION (RAG) OVERVIEW

Retrieval-Augmented Generation (RAG) is an AI framework that combines the strengths of large language models with information retrieval systems. Instead of relying solely on the parametric knowledge encoded in a language model during training, RAG augments the generation process with relevant documents retrieved from an external knowledge base.

The RAG pipeline consists of two main components:

1. RETRIEVAL: When a user query is received, the system embeds the query into a vector representation and searches a document vector store (such as Qdrant or FAISS) for semantically similar chunks. The retrieved chunks form the context provided to the language model.

2. GENERATION: The language model receives the user query concatenated with the retrieved context and generates an answer. Citations can be extracted from the source documents referenced during retrieval.

HYBRID RETRIEVAL combines dense vector search (semantic similarity) with sparse BM25 keyword search to improve recall. Results from both methods are fused using Reciprocal Rank Fusion (RRF) or linear weighting.

RERANKING uses a cross-encoder model (such as ms-marco-MiniLM) to reorder retrieved candidates by their relevance to the query. This two-stage approach improves precision over single-stage retrieval.

CHUNKING is the process of splitting documents into manageable pieces (e.g. 300 tokens with 50-token overlap). Chunk size affects both retrieval precision and context completeness.

EMBEDDINGS are dense vector representations of text, computed by sentence-transformer models like BAAI/bge-small-en-v1.5. The embedding dimension for this model is 384.

VECTOR DATABASE stores embedding vectors along with document metadata. Qdrant supports cosine distance, dot product, and Euclidean distance for similarity search.

MULTI-TENANCY ensures that each user's documents and retrieval results are isolated. Qdrant filters and database ownership checks prevent cross-user data access.
